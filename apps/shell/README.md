# HomeOS shell — рельса приложений

Оболочка HomeOS (вариант 1 «док ОС»): узкая рельса слева, каждое приложение — на весь экран со своим вторым сайдбаром.

## Добавить приложение

Одна строка в `src/apps.tsx`:

```ts
{ id: 'monitoring', title: 'Monitoring', icon: Activity, route: '/monitoring', sidebar: StubSidebar },
```

Оболочка сама даёт ему иконку в рельсе, `⌘N` по порядку, пункт в `⌘K`, маршрут `/monitoring/…` и сворачиваемый сайдбар с запоминаемой шириной (`localStorage: homeos.layout.<id>`). Без `view` — экран «скоро». Ни роутер, ни Caddy править не нужно: Caddy отдаёт оболочку на всё, что не принадлежит tela.

## Клавиши

`⌘K` — палитра, `⌘1…9` — приложения, `⌘\` — сайдбар (на не-Mac — Ctrl). Работают и при фокусе внутри Wiki: фрейм того же origin, оболочка слушает его `keydown` в фазе захвата (поэтому собственный `⌘K` tela перекрыт палитрой оболочки).

## Wiki

Wiki = tela как есть (`apps/wiki` → `frontend/`), в iframe. Маршрутизация в `deploy/homeos/Caddyfile`:

- документ во фрейме (`Sec-Fetch-Dest: iframe`) → SPA tela на любом пути;
- `/assets/*`, файлы корня сборки tela, публичные страницы (`/share`, `/public`, `/u`, …) → tela;
- прямые ссылки tela (`/spaces/…`, `/graph`, `/login`, …) → редирект в `/wiki/…`;
- `/api`, `/ws`, `/dav`, … → бэкенд tela;
- всё остальное → оболочка (`/shell/assets/*` — её ассеты).

URL синхронизируется в обе стороны: навигация внутри tela переписывает `/wiki/…` в адресной строке, смена адреса извне перегружает фрейм.

## Сборка и выкладка

```bash
npm run shell:dev                  # vite на :5180 (из корня репо)
./deploy/homeos/shell.sh           # сборка → /opt/homeos/shell
```
